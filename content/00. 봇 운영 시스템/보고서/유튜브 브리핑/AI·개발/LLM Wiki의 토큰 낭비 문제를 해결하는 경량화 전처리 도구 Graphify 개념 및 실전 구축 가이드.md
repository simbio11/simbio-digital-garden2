# 📌 LLM Wiki의 토큰 낭비 문제를 해결하는 경량화 전처리 도구 Graphify 개념 및 실전 구축 가이드

> [!abstract] 핵심 요약 (Executive Summary)
> - 안드레 카파시의 LLM Wiki는 로우 폴더의 방대한 데이터를 에이전트가 통째로 읽어 처리하므로 과도한 토큰이 낭비되는 결정적 단점이 존재함.
> - 'Graphify'는 LLM Wiki의 핵심 컨셉은 유지하되, 전처리 단계에서 기계적 분석(AST 등)을 도입하여 에이전트가 처리할 뼈대와 구조를 미리 추출하는 하이브리드 전략을 사용함.
> - 기계적 전처리를 통해 에이전트가 직접 원문을 다 읽지 않고도 지식을 구조화할 수 있어, 약 5배 이상의 토큰 절감 효과를 달성함.
> - UV 패키지 관리자를 활용한 파이썬 가상환경 세팅을 거쳐 대상 마크다운 폴더를 지정해 그래피파이 명령어를 실행하는 방식으로 쉽게 구축할 수 있음.
> - 최종 산출물로 생성되는 `그래프 HTML`을 통해 지식 노드 간의 연관성과 연결 구조를 시각적으로 확인할 수 있음.
> - 코덱스(Codex) 환경에서 `graphify-claude-code-install` 또는 `graphify-codex-install` 스크립트를 적용하여 특정 그래피파이 결과물 내에서만 답변하도록 격리 설정이 가능함.
> - 실습 테스트 결과, 방대한 마크다운 문서 기반의 지식 베이스 위에서 불필요한 토큰 소비 없이 정확하게 노드를 탐색해 답변을 도출함.
> - LLM Wiki와 Graphify는 상호 결합하는 것이 아니라 전처리 효율화를 위해 대체·보완하는 별도의 독립적 툴셋으로 운용됨.

### 📑 세부 주제별 심층 정리 (Detailed Breakdown)
#### 1. [기존 LLM Wiki의 한계와 Graphify 등장 배경]
- 안드레 카파시가 제안한 LLM Wiki는 로우 폴더에 자료를 통째로 넣고 인제스트(Ingest) 과정을 거쳐 에이전트가 위키를 구축하고 쿼리에 대응하는 혁신적인 방식을 제공함.
- 정기적인 가드닝(Gardening)과 린트(Lint) 명령어를 통해 중복 제거 및 연결 내용을 갱신하며 유지보수할 수 있으나, 모든 과정을 에이전트가 직접 수행하여 토큰 낭비가 매우 심하다는 치명적인 단점이 있음.
- 이러한 토큰 과다 소비 문제를 해결하기 위해 등장한 것이 'Graphify'이며, LLM Wiki의 위키 컨셉은 그대로 가져가되 입구에서의 전처리 방식을 완전히 혁신함.
- CS 이론 등을 응용하여 에이전트가 원문을 무식하게 읽는 대신, 기계적 분석을 통해 지식의 뼈대와 핵심 구조만 빠르게 추출하여 에이전트에게 제공하는 효율화 메커니즘을 적용함.

#### 2. [Graphify의 하이브리드 전처리 아키텍처 및 메커니즘]
- 1단계에서는 사용자가 제공한 지식 폴더를 LLM 에이전트가 통으로 읽는 것이 아니라, AST 기반의 기계적 분석 툴을 통해 텍스트를 파싱하고 구조화함.
- 이 과정에서 GPT 미니 모델 등 저렴하고 가벼운 서브 에이전트와 미디엄 에포트를 조합하여 비용과 토큰 소비를 극단적으로 줄이면서 병렬 분석을 수행함.
- 기계적으로 추출된 뼈대와 노드 간의 관계 데이터를 에이전트가 보기 좋게 나열하여 하이브리드 형태로 전달함으로써, 에이전트가 훨씬 적은 토큰으로 정확한 지식 구조화를 수행할 수 있게 됨.
- 전처리 작업 완료 후 약 5배 이상의 토큰 절감률을 공식 벤치마크 및 실습 산출물 리포트를 통해 수치로 증명함.

#### 3. [Graphify 프로젝트 실전 구축 단계별 가이드]
- 작업용 새 폴더를 생성하고 터미널에서 `UV 패키지 관리자`를 활용하여 파이썬 가상환경 및 필수 패키지 설치를 진행함.
- 기존 LLM Wiki에서 사용하던 로우 마크다운 데이터 폴더(예: 25개의 마크다운 파일)를 새로운 프로젝트 폴더 내 `notes` 디렉토리에 통째로 복사함.
- 명령어 창에 `graphify notes` 형태의 스킬 명령어를 입력하여 지정된 폴더를 대상으로 기계적 전처리 및 그래프 연결 작업을 구동함.
- 작업이 완료되면 `graphify-out` 폴더 내에 `graph-report.txt`, `graph.json`, `graph.html` 등의 최종 산출물이 생성되며, 특히 HTML 파일을 통해 노드 연결망을 시각적으로 검증할 수 있음.

#### 4. [코덱스(Codex) 환경 연동 및 지식 기반 질의응답 실습]
- 생성된 그래피파이 결과물을 코덱스 환경에서 전용 지식 베이스로 활용하기 위해 `graphify-codex-install` 또는 클로드 전용 인스톨 명령어를 실행함.
- 해당 설정은 에이전트가 일반적인 외부 지식이 아니라 오직 그래피파이로 전처리된 그래프 결과물 안에서만 답변을 탐색하도록 강제하는 격리 레이어 역할을 함.
- 실습 테스트로 "인스타그램 포토 레졸루션(해상도)은 어떻게 설정해야 하는가?"라는 질의를 던졌을 때, 에이전트가 전체 원문을 다 뒤지는 것이 아니라 그래프 구조 내의 연관 노드(사이즈, 썸네일 등)를 정확히 찾아내어 답변함.
- 이를 통해 토큰을 대폭 아끼면서도 정확도 높은 사내 위키 또는 개인 지식 베이스 시스템을 구축할 수 있음을 실증함.

> [!tip] 🔍 주요 키워드 & 데이터 사전
> - **LLM Wiki**: 안드레 카파시가 제안한 개념으로, 로우 데이터를 에이전트가 위키 형태로 자동 변환하고 관리하는 지식 베이스 구축 방식.
> - **Graphify**: LLM Wiki의 전처리 단계에 기계적 분석(AST 등)을 결합하여, 에이전트의 토큰 소비량을 약 5배 이상 절감해 주는 경량화 툴.
> - **UV 패키지 관리자**: 파이썬 환경에서 빠르고 효율적으로 가상환경을 세팅하고 패키지를 설치하기 위해 사용하는 모던 패키지 관리 도구.
> - **토큰 절감률 (약 5배)**: 원문을 에이전트가 직접 읽지 않고 기계적으로 뼈대를 추출해 전달함으로써 달성된 비용 및 토큰 효율성 수치.
> - **Graph HTML**: 그래피파이 전처리 완료 후 생성되는 시각화 파일로, 지식 노드 간의 연관 관계와 클러스터링 상태를 웹 브라우저에서 확인할 수 있음.
