> [!abstract] 핵심 요약 (Executive Summary)
> - **멀티 AI 시대의 컨텍스트 파편화 해결**: ChatGPT, Claude Code, Grok, Codex 등 다수의 AI 도구 활용 시 발생하는 컨텍스트 분산 및 사용량 제한 문제를 하나의 스레드/채널로 통합하여 해결합니다.
> - **로컬 구독 환경의 직교 활용**: 별도의 고비용 API 키 발급 방식 대신, 사용자가 로컬에서 기존에 구독 중인 AI 클라이언트 및 모델 자격 증명을 그대로 활용할 수 있습니다.
> - **암호화 서명 기반 탈중앙 무결성**: 슬랙과 달리 중앙 서버가 아닌 사용자/에이전트 고유의 개인키(Private Key)로 모든 메시지와 커밋을 암호화 서명하여, 서버 권한자도 위·변조가 불가능한 데이터 신뢰성을 확보합니다.
> - **릴레이(Relay) 서버 및 고성능 기술 스택**: Rust 언어로 작성된 릴레이 서버가 메시지 보관/전달을 담당하며, PostgreSQL, Redis, MinIO, 해시 체인(Hash Chain) 감사 로그를 결합한 견고한 아키텍처를 제공합니다.
> - **내장 Git 서버를 통한 코드 공동 작업**: 별도의 GitHub 연동 없이도 릴레이 서버가 직접 Git 레포지토리 역할을 수행하여 에이전트와 사람 간의 코드 커밋 및 작업 이력을 완벽히 추적합니다.
> - **팀 단위 24시간 실시간 협업 지원**: WSS(Websocket) 프로토콜 기반의 지속적 연결을 위해 VPS(예: 8GB RAM, 2 VCPU 사양)에 릴레이를 셀프 호스팅하여 24시간 팀 협업 환경을 구축할 수 있습니다.
> - **슬랙 완벽 대체를 지향하는 UX/UI**: 다이렉트 메시지(DM), 스레드, 반응 이모지, SNS형 방명록 기능인 Pulse 등 익숙한 협업 툴의 경험에 AI 에이전트를 영구적인 팀원으로 편입시킵니다.

### 📑 세부 주제별 심층 정리 (Detailed Breakdown)

#### 1. 멀티 AI 사용 시대의 난제와 Buzz의 등장 배경
- **개발 현장의 멀티 AI 파편화 문제**: 바이브 코딩(Vibe Coding) 및 AI 기반 개발이 일반화되면서 개발자들은 Codex(리팩토링), Claude Code(테스트 코드 작성), Grok(컨텐츠 리서치) 등 여러 AI 도구를 동시에 구동합니다. 이 과정에서 어떤 AI가 어떤 스레드에서 무슨 작업을 수행 중이었는지 기억하기 어렵고 컨텍스트 스위칭 비용이 극대화됩니다.
- **AI 할당량 초과 시의 이관 번거로움**: 특정 AI의 사용량이 다 차면 사용자는 기존 대화 내역을 프롬프트로 재정리하여 다른 AI로 넘기는 복잡한 수동 작업을 반복해야 합니다.
- **사람과 AI 간 단일 협업 공간의 부재**: AI 작업 내역을 인간 팀원과 실시간 공유하고 동일한 맥락에서 대화를 이어갈 수 있는 표준화된 플랫폼이 기존 시장에 존재하지 않았습니다.
- **Buzz의 핵심 제언**: 잭 도시(Jack Dorsey)의 Nostr 생태계 철학을 기반으로 개발된 Buzz는 AI 에이전트와 사람(Human)을 동일한 대등한 참여자로 취급하며, 슬랙(Slack) 인터페이스를 오픈소스로 재해석하여 이 난제들을 완벽히 해결합니다.

#### 2. Buzz의 핵심 기술 아키텍처: 암호화 서명과 릴레이(Relay) 시스템
- **서버 신뢰 모델의 전환 (Slack vs Buzz)**: 일반적인 슬랙은 централизованный 서버 데이터베이스를 신뢰하는 구조이지만, 오픈소스 기반의 Buzz는 호스팅 주체의 데이터베이스 조작 가능성을 방지하기 위해 **암호화 서명(Key Signing)** 방식을 도입했습니다.
- **개인키 기반 메시지 및 리액션 서명**: 모든 사람과 AI 에이전트는 고유한 암호화 키쌍(Public/Private Key)을 부여받으며, 발송되는 메시지·리액션·Git 커밋 등 모든 데이터는 해당 개인키로 서명되어 저장됩니다. 서버 관리자라 할지라도 서명키 없이는 타인을 사칭하거나 데이터를 위조할 수 없습니다.
- **릴레이(Relay) 서버의 역할**: 릴레이는 메시지를 스스로 생성하지 않고, 봉인된 데이터를 유통 및 보관만 담당하는 중계 서버입니다. 데이터 무결성이 보장되므로 릴레이 서버가 해킹당하더라도 본인 인증 정보 및 데이터 신뢰성은 유효합니다.
- **실시간 통신과 웹소켓(WSS)**: 단발성 HTTP 요청이 아닌, 끊김 없는 지속적인 실시간 상태 동기화를 위해 `wss://` (Websocket Secure) 프로토콜을 필수로 요구합니다.

#### 3. 인프라 스택 및 셀프 호스팅 구동 환경 (Hostinger VPS & WSS)
- **로바스트한 기술 스택 구조**:
  - **Relay Core**: Rust 기반으로 작성되어 극도로 빠르고 안정적인 워크스페이스의 단일 진실 출처(Single Source of Truth) 역할을 수행.
  - **데이터베이스 & Caching**: 데이터 저장소로 PostgreSQL을 사용하며, 실시간 메시징 처리를 위해 Redis를 탑재.
  - **파일 저장소**: AWS S3 인프라를 에뮬레이트하기 위해 로컬 개발/운영 표준 컨테이너인 MinIO 적용.
  - **감사 로그(Audit Log)**: Hash Chain으로 결합되어 관리자조차 로그의 삭제나 수정이 불가능하도록 무결성 보장.
- **24시간 팀 협업을 위한 VPS 셀프 호스팅**: 로컬 PC에서 릴레이를 실행하면 컴퓨터가 켜진 동안만 협업이 가능하므로, 클라우드 VPS 구축이 권장됩니다.
  - **권장 인프라 사양**: 최소 8GB RAM, 2 vCPU 코어 이상을 권장 (Hostinger KVM 2 플랜 등, 월 약 1만 원대 수준 비용).
  - **설치 및 연동**: VPS 호스팅 대시보드에서 Buzz 앱을 원클릭 배포한 후, 부여받은 Public Key와 `wss://` 엔드포인트를 Buzz 데스크톱 클라이언트에 입력하여 커뮤니티 연결을 완료합니다.

#### 4. 멀티 에이전트 설정 및 유연한 LLM 백엔드 스위칭 실전 가이드
- **에이전트 연동 프로토콜 (ACP)**: Buzz는 ACP(Agent Control Protocol) 방식을 통해 백그라운드 프로세스로 띄워진 에이전트를 시스템에 결합시킵니다.
- **백엔드 LLM 모델의 다변화**:
  - 예: `유튜브 컨텐츠 리서처`에 **Grok 4.6** 지정
  - 예: `유튜브 썸네일 제너레이터`에 **Codex 5.6 Tera** 지정
  - 예: `프로그래머`에 **Claude Code Opus (100만 컨텍스트)** 지정
  - 추가로 Hermes, Kimi 등 사용자 환경에 설치된 다양한 러닝타임/모델 자유롭게 가속 추가 가능.
- **시스템 프롬프트(Instructions) 지정**: 에이전트마다 특정 페르소나 및 지침을 부여하여 채널 내에서 자율적으로 역할을 분담하게 만듭니다.
- **컨텍스트 유지 및 백엔드 교체**: 작업 도중 백엔드 모델을 Claude에서 Grok으로 스위칭하더라도, 동일 스레드 내의 이전 맥락 데이터(Context)는 영구히 유지되므로 벤치마킹 및 업무 연속성 확보가 용이합니다.

#### 5. 내장 Git 서버와 Pulse/스레드 기반의 오인원(All-in-One) 협업 워크플로우
- **내장 Git 레포지토리와 완전한 코드 추적성**: 릴레이 서버가 자체 Git 서버 기능을 내장하여 GitHub 없이도 프로젝트 저장소를 구동합니다. 에이전트가 코드를 작성하고 커밋하면, 사이드바의 'Project' 탭에서 어떤 에이전트가 어떤 암호화 서명으로 커밋을 남겼는지 시각적으로 검증할 수 있습니다.
- **에이전트 간 병열 작업 협업**: 채널에서 다수의 에이전트(@멘션)에게 동시에 과업을 부여하면, 리서처가 뉴스를 탐색하는 동안 프로그래머 에이전트는 병렬적으로 랜딩 페이지 뼈대 코드를 작성하여 프로젝트 저장소에 반영하는 유기적 협업을 보여줍니다.
- **Pulse(방명록/SNS) 및 Inbox 기능**: 단순 메신저를 넘어 AI와 인간이 일상의 작업 일지나 커스텀 소식을 공유하는 내부 SNS형 'Pulse' 기능과 본인에게 태그된 요청만 모아보는 'Inbox'를 지원합니다.
- **한계점 및 향후 전망**: 현재 Research Preview 단계로 일부 태그 미인식 등의 버그나 워크플로우 엔진의 복잡도가 존재하지만, 로컬 구독 자원 활용과 서명 기반 탈중앙 협업 구조는 향후 슬랙을 완전히 대체할 잠재력을 지니고 있습니다.

> [!tip] 🔍 주요 키워드 & 데이터 사전
> - **Buzz (버즈)**: Nostr 생태계 기술을 기반으로 개발된 AI 에이전트-인간 통합 협업 오픈소스 플랫폼.
> - **릴레이(Relay) 서버**: Rust로 구현된 중계 서버로, 메시지를 직접 생성하지 않고 암호화 서명된 봉인 데이터를 보관/전달함.
> - **ACP (Agent Control Protocol)**: 외부 AI 에이전트를 Buzz 시스템 프로세스로 바인딩해 주는 인터페이스 프로토콜.
> - **Hash Chain 감사 로그**: 데이터 변경/삭제 시 무결성이 깨지도록 설계된 블록체인 형태의 수정 불가 로그 시스템.
> - **MinIO**: AWS S3 API와 호환되는 오픈소스 오브젝트 저장소로, 로컬/셀프호스팅 환경에서 파일 관리를 담당.
> - **WSS (Websocket Secure)**: 24시간 양방향 실시간 통신을 유지하기 위해 사용되는 웹소켓 암호화 프로토콜.
> - **권장 VPS 인프라 스펙**: 릴레이의 안정적 구동을 위해 8GB RAM, 2 vCPU 이상 권장 (월 1만 원대 소요).
