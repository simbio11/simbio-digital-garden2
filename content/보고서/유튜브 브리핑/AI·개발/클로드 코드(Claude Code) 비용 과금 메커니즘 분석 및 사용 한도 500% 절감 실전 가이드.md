> [!abstract] 핵심 요약 (Executive Summary)
> - **비용의 본질**: AI 요금은 표면적으로 토큰 개수로 부과되나, 실제 본질은 GPU가 해당 토큰을 처리하는 데 소요된 **'추론 시간(Compute Time)'**에 기반합니다.
> - **출력 토큰의 높은 단가**: 출력(Output) 토큰은 직전 토큰을 참조하며 순차 계산(Decode)해야 하므로, 병렬 처리가 가능한 입력(Input) 토큰보다 단가가 **약 5배 비쌉니다**.
> - **프롬프트 캐싱의 절감 효과**: 이전 대화 맥락을 재사용하는 캐싱(Prompt Caching)을 활용하면 입력 토큰 비용을 전가 대비 **10분의 1(90% 할인)** 수준으로 대폭 낮출 수 있습니다.
> - **컨텍스트 재전송 법칙**: "어떤 것도 한 번만 전송되지 않는다"는 원칙에 따라, 대화 중 읽은 파일·명령어 출력·MCP 설정을 포함한 모든 맥락이 매 요청마다 반복 재전송됩니다.
> - **캐시 무효화 주의사항**: 대화 도중 모델/Effort 설정을 변경하거나 1시간 이상 유휴 상태가 되면 서버 캐시가 만료되어 대화 전체가 정가로 재계산됩니다.
> - **프롬프트 지시 최적화**: 모호한 질문 대신 파일명 지정 및 **`@ 파일 멘션`**을 활용하면 불필요한 파일 탐색 과정에서 발생하는 컨텍스트 오염과 토큰 낭비를 차단할 수 있습니다.
> - **서브 에이전트(Sub-agent) 활용**: 수천 줄의 로그 분석 등 대용량 작업은 독립 컨텍스트를 사용하는 서브 에이전트에 위임하여 메인 세션의 컨텍스트를 깨끗하게 유지해야 합니다.
> - **비용 영향도 TOP 4**: 엔트로픽 공식 블로그 기준 비용 낭비의 주요 원인은 **1위 긴 세션 유지, 2위 과도한 컨텍스트 적재, 3위 과한 모델/Effort 설정, 4위 캐시 파괴 행위** 순입니다.

### 📑 세부 주제별 심층 정리 (Detailed Breakdown)

#### 1. AI 토큰 과금 메커니즘과 입력/출력 단가 차이의 원리
- AI 모델 이용료의 고지서 표기 단위는 토큰 개수이지만, 서버 측 실제 원가는 GPU 컴퓨터가 모델 가중치(Parameters)를 거쳐 계산을 수행하는 '시간'입니다.
- 연산 시 입력 토큰(Input) 처리 과정인 **프리필(Prefill)**은 지문 전체를 일괄 병렬 처리할 수 있어 상대적으로 가볍고 저렴합니다.
- 반면 출력 토큰(Output) 처리 과정인 **디코드(Decode)**는 다음 단어를 생성하기 위해 직전 단어까지의 모든 맥락을 연달아 계산해야 하므로 연산 부하가 매우 큽니다.
- 이에 따라 출력 토큰 단가는 입력 토큰보다 **약 5배 비싸게 책정**되며, 여기에는 화면에 출력되는 답변뿐만 아니라 모델 내부의 **사고 토큰(Thinking Token)**과 도구 실행 요청 비용이 모두 포함됩니다.
- 사고 깊이를 결정하는 `Effort` 설정이 'High'로 지정되어 있으면 비싼 출력 토큰이 급증하며, 이 설정은 다음 세션까지 이월되므로 세션 개시 시 반드시 재확인이 필요합니다.

#### 2. 프롬프트 캐싱(Prompt Caching)의 동작 원리와 캐시 무효화 조건
- 클로드 코드는 이전 대화의 앞부분 연산 결과를 서버 메모리에 저장해 두었다가 재사용하는 프롬프트 캐싱 시스템을 자동 운영합니다.
- 최초 저장 시에는 보관료가 붙어 정가 대비 최대 약 2배 비용이 발생하지만, 2번째 대화부터 재사용 시에는 **정가의 0.1배(90% 할인)**로 가격이 대폭 하락합니다.
- 예컨대 20회 대화를 주고받을 때 미캐싱 시 총비용이 20 단위라면, 캐싱 적용 시 `2(최초 저장) + 1.9(19회 재사용) = 3.9 단위`로 **약 5배 이상의 비용 절감** 효과를 거둡니다.
- 그러나 캐시는 기차 칸처럼 순차적으로 비교되므로, 앞쪽 대화 맥락이 변하면 뒤쪽 캐시가 도미노처럼 전부 깨집니다.
- 세션 중간에 모델이나 Effort 변경(꼬리표 불일치), `/compact` 명령 실행(대화 구조 교체), **1시간 이상 유휴 상태**(서버 캐시 만료)가 발생하면 캐시가 무효화되어 전가 계산으로 전환됩니다.

#### 3. 컨텍스트 누적 억제를 위한 효율적인 프롬프트 및 명령어 구사법
- "어떤 것도 한 번만 전송되지 않는다"는 원리처럼 대화에 한 번 들어온 파일 내용이나 터미널 명령어 출력 결과는 세션 종료 시까지 매번 재전송됩니다.
- 연결만 해두고 쓰지 않는 **MCP(Model Context Protocol) 서버**의 도구 설명서가 수천~수만 토큰을 고정 점유하므로, 미사용 커넥터는 즉시 정리해야 합니다.
- 모호하게 "오류 수정해 줘"라고 명령하면 프로젝트 전체를 탐색하며 무수한 파일이 컨텍스트 짐으로 남지만, **`@파일명` 멘션**을 쓰면 파일 읽기 요청 과정 자체가 생략되어 프롬프트 전송 단계에서 즉시 첨부됩니다.
- 단, 동일 대화 세션 내에서 같은 파일을 중복 `@ 멘션`하면 사본이 사본을 불러와 컨텍스트가 늘어나므로 두 번째부터는 파일 이름만 텍스트로 언급하는 것이 올바릅니다.
- 현재 컨텍스트에 어떤 짐이 실려 있는지 파악하려면 **`/context`** 명령어를 실행하여 항목별 토큰 점유율을 주기적으로 체크해야 합니다.

#### 4. 세션 관리 전략: `/clear`, `/compact`, `/rewind`의 올바른 활용
- 하나의 긴 세션을 오래 유지하는 것은 눈덩이처럼 불어난 과거 기록을 매번 재전송하게 만사므로 짧은 세션 여러 개로 분할 작업하는 것이 비용 측면에서 훨씬 유리합니다.
- 완벽히 새로운 주제로 전환할 때는 **`/clear`**를 실행해 대화 기록을 백지로 만들고 가볍게 재출발해야 합니다.
- 기존 맥락을 유지해야 하지만 컨텍스트가 무거워진 경우 **`/compact`**를 사용하되, 뒤에 `"핵심 결정 사항과 파일 경로는 남겨줘"`와 같은 세부 가이드를 덧붙여 필요한 정보만 압축 재구성이 가능합니다.
- 특히 `/compact`는 캐시가 살아있는 동안(1시간 이내) 실행해야 요약본 생성 시 입력 비용을 10분의 1 단가로 처리할 수 있습니다.
- 최근 몇 번의 대화가 오작동해 방황한 경우에는 캐시 전체를 깨뜨리는 `/compact` 대신, 뒤쪽 불량 대화 칸만 잘라내어 앞쪽 캐시를 보존하는 **`/rewind`** 명령어를 쓰는 것이 효율적입니다.

#### 5. 서브 에이전트(Sub-agent)를 활용한 대용량 작업 분리 처리
- 서브 에이전트는 메인 클로드가 특정 세부 과업을 전담시키기 위해 독립적인 별도 컨텍스트로 생성하는 하위 클로드입니다.
- 서브 에이전트는 메인 대화의 기존 세션 기록을 공유받지 않는 '백지 상태'에서 시작하며, 작업 완료 후 **최종 요약 결론 1줄/보고서만** 메인 대화로 반환합니다.
- 분석 과정에서 읽은 수천 줄의 로그 파일이나 임시 탐색 기록은 서브 에이전트 종료와 함께 전부 폐기되어 메인 세션의 컨텍스트 책상을 깨끗하게 유지해 줍니다.
- 서브 에이전트 역시 작업 토큰 비용은 발생하므로 소규모 작업에는 불필요하지만, "읽을 양은 많으나 남길 결과물은 적은" 수천 줄 로그 분석 등의 작업에 비해서는 압도적인 절감 효과를 제공합니다.
- 실행 시 별도 명령 없이 프롬프트로 `"이 파일은 서브 에이전트로 검토해서 결과만 보고해 줘"`와 같이 구어체로 지시하면 적용됩니다.

> [!tip] 🔍 주요 키워드 & 데이터 사전
> - **프리필 (Prefill)**: 대화 입력 맥락을 미리 읽고 머릿속을 채우는 과정. 병렬 연산이 가능하여 가격이 저렴함.
> - **디코드 (Decode)**: 답변, 사고 과정, 도구 실행 등을 순차적으로 한 토큰씩 생성하는 과정. 연산 부하가 커 **입력 단가의 약 5배** 과금.
> - **프롬프트 캐싱 (Prompt Caching)**: 동일 맥락 전송 시 계산 결과를 서버에 보관해 **10분의 1 단가(90% 할인)**로 처리하는 기술.
> - **사고 토큰 (Thinking Token)**: AI가 답변을 내놓기 전 내부적으로 수행하는 추론 연산. 눈에 보이지 않지만 출력 토큰 단가로 정산됨.
> - **`/context`**: 현재 세션에 적재된 MCP, 파일, 대화 기록의 토큰 점유율을 확인하는 명령어.
> - **`/rewind`**: 최근 오작동한 대화 단계만 뒤에서 잘라내어 기존 앞부분 캐시 유효성을 보존하는 명령어.
> - **서브 에이전트 (Sub-agent)**: 메인 컨텍스트 오염 없이 대용량 탐색/분석 작업을 별도 세션에서 처리하고 결과만 수령하는 독립 에이전트.
> - **엔트로픽 비용 영향도 랭킹**: 1위 긴 세션 유지 > 2위 과도한 컨텍스트 적재 > 3위 과한 모델/Effort 설정 > 4위 캐시 파괴 행위.
